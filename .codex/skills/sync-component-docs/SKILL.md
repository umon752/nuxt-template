# 同步元件文件

在同一次變更中維持 `app/components` 與 `docs/components` 同步。檢查並更新所有受影響的文件之前，不得將元件任務視為完成。

## 執行流程

1. 編輯前先閱讀專案根目錄的 `AGENTS.md` 與元件原始碼。
2. 檢查元件現有文件、鄰近元件的文件、`docs/components/README.md`，以及 `app/pages/sample.vue` 中的相關用法。
3. 確認哪些公開行為受到影響：props、預設值、事件、事件 payload、插槽、插槽 props、公開方法、渲染結構、鍵盤或指標操作、無障礙、i18n、樣式輸入或清理行為。
4. 在實作元件變更的同時更新文件。
5. 新增、重新命名、移動、刪除元件，或元件摘要有實質變更時，更新元件索引。
6. 交付前驗證原始碼、文件、範例與連結。

## 對應文件路徑

在 `docs/components` 下保留元件的原始目錄結構，再以不含副檔名的 Vue 檔名建立目錄，並在其中建立 `README.md`。

- `app/components/Accordion.vue` 對應 `docs/components/Accordion/README.md`。
- `app/components/counter/Counter.vue` 對應 `docs/components/counter/Counter/README.md`。
- `app/components/editor/EditorContent.vue` 對應 `docs/components/editor/EditorContent/README.md`。

保留專案現有路徑的大小寫。重新命名或移動元件時，將文件移到新的對應路徑，並修正所有受影響的連結。刪除元件時，除非使用者明確要求保留封存文件，否則移除過期的文件與索引項目。

## 維護文件內容

使用繁體中文撰寫文件，並遵循鄰近元件文件的既有結構。所有敘述都必須從原始碼推導，不得虛構 API 或使用範例。

依元件實際情況包含以下內容：

- 元件用途與有效的原始碼連結。
- 使用實際 Nuxt 自動匯入名稱的基本範例。
- Props 的精確 TypeScript 型別、預設值、有效值與受控狀態行為。
- Emits 的精確事件名稱、payload 型別與觸發條件。
- Slots 與 slot props。
- 公開方法或命令式 API。
- 互動行為、方向或 fallback 規則、計時器、清理機制與邊界情況。
- 無障礙語意、鍵盤操作、ARIA 行為與相關 i18n 語系鍵值。
- 屬於公開 API 的樣式 props 或 Tailwind 自訂方式。
- 必要的安全限制，例如受信任 HTML 的使用要求。

移除過期的說明與範例，不要只在文件末端持續追加內容。某個 API 區段不存在時，可以省略；若有助於使用者理解，也可以明確說明元件不需要額外輸入。

## 處理不同變更類型

### 建立元件

建立對應的 `README.md`、將元件加入 `docs/components/README.md` 的適當表格，並記錄所有初始公開行為。

### 修改或重構元件

每次變更元件時都要檢查對應文件。公開行為、無障礙、i18n、渲染語意或支援用法受到影響時，更新所有相關段落與範例。若只有內部重構且文件內容仍完全正確，不要製造無意義的文件變更；交付時必須明確說明已檢查文件且不需要修改。

### 重新命名或移動元件

移動對應文件，更新原始碼連結與使用範例，更新元件索引，並在整個 `docs` 目錄搜尋舊元件名稱與舊路徑。

### 刪除元件

移除對應文件與索引項目，接著在 `docs` 目錄搜尋過期引用。刪除屬於破壞性操作，執行前確認使用者的要求已明確包含刪除目標。

## 保持範例正確

使用可依目前實作通過編譯的範例。受控元件必須符合本專案的單向資料流原則：透過 props 傳入狀態，並透過 emit 事件更新父層持有的狀態。只有元件確實實作對應契約時，文件才能使用 `v-model`。

只有在使用者要求展示，或現有展示因本次變更而失效時，才更新 `app/pages/sample.vue`。不要加入與任務無關的展示內容。

## 驗證結果

完成前執行以下檢查：

1. 使用 `rg` 搜尋過期名稱、路徑、props、事件名稱與範例。
2. 確認每個 Markdown 原始碼連結都指向存在的檔案。
3. 依照 `AGENTS.md` 及其連結的提交前檢查規範，執行專案適用的格式化、typecheck、測試、lint 或 build 指令。
4. 執行 `git diff --check`。
5. 檢查 `git diff`，確認元件、對應文件與索引一致，並保留使用者其他未完成的變更。

最終交付時，列出本次建立或更新的文件路徑。若內部變更不需要修改文件，說明已檢查對應文件且內容仍然正確。
